- 1) Hashing of key: When you add data, Java takes the key and calls its hashCode() to generate a number.

- 5) Retrieving data 

When you call get(key): 

- Java finds the bucket using hashCode() 

- Then uses equals() to find the exact key 

- Returns the value

**241. Explain the internal working of LinkedHashMap?**

It stores data as key–value pairs like HashMap, but it also keeps a doubly linked list to remember the order of elements. 

Lets understand, gow it works step by step 

###### 1) Hashing like HashMap 

Key’s hashCode() decides the bucket. Entry is stored in an internal array. 

###### 2) Maintaining order 

Along with storing in a bucket, LinkedHashMap connects entries using a doubly linked list. This list keeps track of insertion order (or access order if configured).

When you get a value, HashMap logic is used (hashCode + equals). When you iterate, it follows the linked list to return elements in order. 

###### 4) Collision handling 

Same as HashMap (linked list / tree inside bucket).


**242. Explain the internal working of TreeMap?**

A TreeMap stores data as key–value pairs and keeps them sorted by keys. 

Internally, it uses a special tree structure called a Red-Black Tree. 

How it works step by step 

- 1) Sorted storage: When you add a key–value pair, TreeMap compares the key with existing keys and places it in the correct sorted position. 

- 2) Red-Black Tree structure 

Entries are stored in a self-balancing tree: Each node has a key, value, left child, and right child. The tree automatically balances itself after insertion/deletion 

- 3) Searching 

To find a value: TreeMap compares the key step by step in the tree. Moves left or right until the key is found 

- 4) No hashing used 

Unlike HashMap, TreeMap does not use hashCode(). 

It uses: compareTo() (natural ordering), or Comparator (custom sorting) 



- **Why does TreeMap require natural ordering or a comparator?** TreeMap keeps keys sorted. To sort, it must compare keys. So it needs either: • Natural ordering (Comparable), or 

- • A custom Comparator 

- Without comparison, it cannot decide where to place keys in the tree.
